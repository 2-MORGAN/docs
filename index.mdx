## Ce que fait Nimbus

Nimbus prend le code de votre dépôt GitLab et le met en ligne pour vous. Vous choisissez une cible de déploiement, puis Nimbus construit l'image et surveille l'exécution. Chaque application web reçoit une adresse HTTP dès son premier déploiement. Quand vous voulez du HTTPS avec des protections (CORS, débit, taille des requêtes), vous activez la passerelle. Vous n'écrivez ni manifeste Kubernetes ni pipeline à la main.

Une application Nimbus sait aussi stocker vos variables et secrets, brancher une base PostgreSQL, planifier ses horaires d'activité, autoscaler selon la charge et vous alerter sur Discord en cas de panne. Tout se pilote depuis l'interface web ou depuis la CLI `nimbus`.

## Les deux façons de travailler

L'interface web (`https://cnp.2morgan.fun`) montre chaque action avec ses boutons et ses formulaires. La CLI `nimbus` fait la même chose en ligne de commande, ce qui convient aux scripts et aux agents. Quand une action n'existe que d'un seul côté, la page concernée le dit en toutes lettres.

Concrètement, votre premier parcours tient en trois gestes : connectez-vous, enregistrez votre jeton GitLab, puis créez votre première application. Chacune de ces étapes a sa page dans le tableau ci-dessus, alors avancez dans l'ordre et vérifiez chaque résultat avant de passer à la suite.

Pour comparer les deux côté par côté, lisez [interface ou CLI](/cli/interface-ou-cli).
